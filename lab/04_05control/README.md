# Lab 4+5 — Lif / Lwhile

Run: `uv run compiler.py <file.lif> [--registers n]`

## Non-obvious elements

- **shrink**: `and`/`or` become `IfExp` (`a and b` → `b if a else False`, `a or b` → `True if a else b`); chains are folded so the leftmost operand is tested first.
- **remove_complex_operands**: the test of an `if` is not atomized. The temporaries of a `while` test are kept *inside* the test, in a `Begin`, so they are recomputed on every iteration. Temporaries of `IfExp` branches stay inside that branch (`Begin`).
- **explicate_control**: the program's entry block is named `start`. `create_block` reuses a block that is already a single `goto`, so nested conditionals do not duplicate code. For `while`, the header label is created before the body, so the body can jump back to it.
- **explicate_pred**: an atomic test is compared against `False` with the branches swapped (Python truthiness, e.g. `if 5:`); a non-atomic test (e.g. `input_int()`) is first bound to a temporary.
- **select_instructions**: `not (a < b)` uses the negated condition code directly; `not x` uses `xorq $1`. `True`/`False` become `1`/`0`.
- **Liveness**: computed across blocks with a fixpoint worklist (works for loops). `live_after(jmp L) = live_before(L)`, `live_after(j<cc> L) = live_before(L) ∪ live_before(next)`.
- **Register allocation**: one home map for the whole program, so a variable keeps the same location in every block. Callee-saved registers are pushed in `main` and popped in `main_conclusion`.

## Tests

Each test is a program `tests/<name>.lif`, its input `tests/<name>.in`, the expected output `tests/<name>.out` (produced by running the program with Python) and the assembly generated by this compiler `tests/<name>.s`. To run one:

```
uv run compiler.py tests/<name>.lif > t.s && gcc t.s runtime.c -o t && tr ' ' '\n' < tests/<name>.in | ./t | diff - tests/<name>.out
```

| test | covers |
|---|---|
| short_circuit | short-circuit evaluation of `and`/`or` |
| if_exp_stmt | if expressions and statements |
| logical | logical expressions in assignments and conditions |
| temps_scope | temporaries in branches and loop conditions |
| nested_if | nested conditionals (no duplicated blocks) |
| nested_loops | nested `while` |
| loop_liveness | liveness and register allocation with loops |

## Known limitations

- `print` of a boolean prints `1`/`0` (the runtime only has `print_int`).
- `//` and `%` truncate toward zero (`idivq`), unlike Python for negative operands.
- Integers are 64-bit.
